## Quick start

1. Start **Docker** (Docker Desktop, OrbStack, Colima or Docker Engine with Compose v2).
2. Open **REDAXO** in the activity bar → **+** (New Instance).
3. Enter a name, e.g. `customer-shop` → choose **REDAXO**.
4. After about a minute a notification offers **Open backend** and **Copy password**.

The name is also the address: **https://customer-shop.localhost**.
The first start of a PHP version builds the Docker image – this takes a few minutes, afterwards starting takes seconds.

**Recommended:** run **REDAXO: Trust HTTPS Certificates (mkcert)** once – the browser then trusts all local certificates.
Install mkcert: macOS `brew install mkcert nss` · Windows `winget install FiloSottile.mkcert` · Linux `sudo apt install mkcert libnss3-tools`.

## The instances view

| Icon | Meaning |
|---|---|
| green check | instance is running |
| empty circle | instance is stopped |
| warning | only some containers are running – “Rebuild Containers” helps |

**▶ / ■** next to the name starts or stops the instance, the **house** opens the backend.
Expand an instance to see:

| Item | Click |
|---|---|
| Frontend / Backend | opens the site in the browser |
| Domains | manage additional host names |
| Login | copies the admin password |
| Database | shows all access data to copy |
| Folder | opens the instance in VS Code |

All other actions are in the **context menu** (right click). The **Services** view shows the HTTPS proxy, Mailpit and Adminer.
The status bar shows how many instances are running.

## Domains and HTTPS

A shared proxy serves every instance via HTTPS:

- `https://<name>.localhost` and every sub domain `https://*.<name>.localhost` work automatically.
- Add more domains such as `shop.localhost` or `customer-b.localhost` with **Domains…** – perfect for testing
  YRewrite multi-domain setups locally: enter the same domains in YRewrite.
- `*.localhost` always points to your computer – no hosts file needed.
- If ports 80/443 are taken (e.g. by another local web server), the proxy picks free ports automatically –
  addresses then look like `https://customer.localhost:8443`. The instances view always shows the correct address.

Every instance is also reachable directly via `http://localhost:<port>` (see **Access Data…**).

## Working with an instance

| Task | How |
|---|---|
| Clear cache | right click → **Clear Cache** |
| REDAXO console | right click → **REDAXO Console…**, e.g. `package:install yform` |
| Shell in the container | right click → **Open Shell** (Composer, git, ImageMagick, vips … are installed) |
| SQL | right click → **Open SQL Console** or **Open Database in Adminer** (the password is copied to the clipboard) |
| Read e-mails | Services → **Mailpit** – all mails of all instances end up there |
| Additional database | right click → **Create Additional Database…** |
| Switch PHP | right click → **Change PHP Version…** (data is kept) |
| Upgrade MariaDB | right click → **Upgrade MariaDB…** (upgrades only – export first if unsure) |
| Logs | right click → **Show Container Logs** or **Show REDAXO System Log** |

**Customizing:** `docker/custom-setup.sh` in the instance folder runs inside the container on every start
(extra packages, PHP settings, …). Own compose additions go into `docker-compose.override.yml` –
`docker-compose.yml` is generated by the extension.

## REDAXO 6

The wizard offers two variants of the development version (PHP 8.5 or newer):

- **REDAXO 6** – Composer project (`redaxo/project:6.x-dev`) to try it out and build sites.
- **REDAXO 6 Core** – clone of `redaxo/core` (branch `6.x`) to contribute. The dev instance lives in `project/`,
  the web root contains the `AGENTS.md` of the core repository with its coding standards.

Database, mailer and base URL are configured via environment variables (`DATABASE_URL`, `MAILER_DSN`, `REX_BASE_URL`).
`console migrate` runs automatically on every start. AddOns are added with `composer require`.

## AI: Copilot and Claude (MCP)

### Copilot

- Ask **`@redaxo`** in the chat: `/list`, `/info shop`, `/start shop`, `/console shop cache:clear`,
  `/query shop SELECT name FROM rex_article`, `/logs shop`, `/help` – or just ask.
- In **agent mode** the `#redaxo-…` tools are available. Changing actions ask for confirmation.

### Claude Code and Claude Desktop

The extension ships an **MCP server** so that Claude can operate your instances just like you:

1. Run **REDAXO: Connect Claude (MCP)**.
2. Choose **Claude Code** (all projects, also the Claude Code extension for VS Code) or **Claude Desktop**.
3. Ask Claude, e.g. “List my REDAXO instances”.

What Claude can do:

| Tool | Example |
|---|---|
| `list_instances` | “Which instances are running?” |
| `get_instance` | “How do I connect to the database of shop?” |
| `list_versions` | “Which PHP versions are available?” |
| `create_instance` | “Create a REDAXO 6 instance test6.” |
| `start_instance` / `stop_instance` | “Start shop, stop all others.” |
| `redaxo_console` | “Install YForm in shop.” |
| `query_database` | “How many articles are offline?” (read-only unless writing is explicitly allowed) |
| `get_logs` | “Are there PHP errors in shop?” |
| `set_domains` | “Add shop-b.localhost to shop.” |

Passwords are only returned when explicitly asked for.

Every instance also contains an **`AGENTS.md`** (plus `CLAUDE.md` and `.mcp.json`) with all facts about the environment:
container names, paths, console, database host. Copilot and Claude Code read it automatically when the instance folder
is open. Refresh it with right click → **Update AI Instructions (AGENTS.md)**.

## Xdebug

Right click → **Start Debugging (Xdebug)** does everything in one step:

- enables Xdebug in the instance (it restarts briefly),
- offers to install the “PHP Debug” extension if needed,
- starts the debugger with the correct path mapping and writes `.vscode/launch.json` into the instance folder.

Then set a breakpoint and open the page with `?XDEBUG_TRIGGER=1` (or use the “Xdebug helper” browser extension).
**Toggle Xdebug** only switches it on or off without starting the debugger.

## Errors in the Problems panel

PHP and REDAXO errors of running instances appear in VS Code's **Problems** panel automatically – with file and line,
one click jumps there. REDAXO's `system.log` and the PHP error output of the container are read; only errors that
occur after VS Code started are shown. Clear them with **Clear REDAXO Problems**.

## Snapshots

Right click → **Create Snapshot…** saves the database and files of the instance (without caches) – ideal before an
AddOn update, a migration or an experiment. **Snapshots…** restores or deletes them. Restoring resets database and
files exactly to the saved state; a git repository (`.git`) is left untouched. Snapshots live in `.snapshots/` in the
instance folder.

## Git

- **New Instance from Git Repository…** (also in the wizard under “From a Git repository…”): clones a project with your
  git credentials, detects REDAXO 5, REDAXO 6 or a PHP project including the document root and sets everything up.
  REDAXO 6 gets `composer install` and the setup, REDAXO 5 a fresh installation with an empty database.
- **Set Up Git…** (right click): puts the project folder (`project/`) under git – with a `.gitignore` for REDAXO
  (cache, `config.yml`, logs, media), an optional remote and a first commit. Then use VS Code's Source Control view.

## More tools

- **Duplicate…** copies an instance including its database under a new name – e.g. to test an update safely.
- **Open in Dev Container** opens VS Code inside the web container (“Dev Containers” extension). PHP tools such as
  Intelephense then use exactly the PHP version of the instance.
- **Resources:** hovering an instance shows CPU, RAM and disk usage in the tooltip.

## Export, import and 1.x instances

- **Export…** creates a `.tar.gz` with all files and a database dump.
- **Import Instance…** creates a new instance from it – also from exports of version 1.x. The database is imported
  on the first start and the REDAXO server URL is adjusted.
- **Instances of version 1.x** are still detected and work as before. **Modernize Instance…** converts them:
  a full backup is created first (`.redaxo-mi/backups/`), files, database, ports, credentials and container names are
  kept, the old configuration is moved to `.legacy/`.

## Installation and updates

The extension is distributed via the [GitHub releases](https://github.com/FriendsOfREDAXO/redaxo-multi-instances-vscode/releases).
To install a new version: download the `.vsix` → Extensions view → **…** → **Install from VSIX…** →
**Developer: Reload Window**. VS Code does not update such extensions automatically; settings and instances are kept.

**From version 1.x:** simply install over the old version. All instances keep working unchanged; modernize them one by
one whenever you like (see above). The `<name>.local` entries 1.x added to `/etc/hosts` are only needed for instances
with HTTPS that have not been modernized.

## Troubleshooting

| Problem | Solution |
|---|---|
| “Docker is not running” | Start Docker Desktop – the view updates automatically. |
| Browser warns about the certificate | Install mkcert and run **Trust HTTPS Certificates**. Restart Firefox if needed. |
| Page shows “… is not running” | The instance is stopped – click ▶ in the list. |
| Frontend shows an error after installation | Normal for an empty REDAXO: create a start article in the backend. |
| First start takes long | The image for the PHP version is built once. Progress: **Show Log**. |
| Instance does not start / warning icon | Right click → **Rebuild Containers**. Files and database are kept. |
| Port conflicts | **Maintenance… → Fix port conflicts** |
| Disk space | **Maintenance… → Clean up Docker** removes containers and images of deleted instances. |
| An unknown domain shows a list of instances | The domain belongs to no instance – add it to the instance via **Domains…**. |
| Addresses need a port (`:8443`) | Another local server uses 80/443 (e.g. Atelier, yerd, Herd, Valet, MAMP). Stop it – the proxy moves back automatically on the next instance start. For yerd also run `sudo pfctl -a dev.yerd -F nat`. **Maintenance… → Why do the addresses need a port?** shows who uses the ports. |
| Instances are somewhere else | **Maintenance… → Change instances folder…** or setting `redaxo-instances.instancesPath` |

Detailed logs of all actions: **REDAXO: Show Log**.
